# Little Day

**Little Day** is a personal AI-powered planner that I'm building to help me manage college, personal goals, habits, and everything else that tends to pile up during a busy week.

I wanted something beyond a normal to-do list.

If I have a goal like *"learn Transformers"* or *"finish a project"*, simply writing it down doesn't really help. I need to figure out what the goal actually involves, break it into smaller pieces, and find time for those pieces around classes, commitments, and other things I already have planned.

That's the problem I'm trying to solve with Little Day.

## What Little Day does

Little Day lets me keep track of:

* Tasks
* Long-term goals
* Habits
* Classes and other commitments
* Scheduled time blocks

The interesting part is the goal planning.

I can give Little Day a larger goal, and the AI breaks it down into smaller, actionable tasks. Those tasks can then be scheduled around the commitments already in my calendar.

For example:

```text
Goal:
Learn the Transformer architecture
```

can become something like:

```text
Read the introduction of Attention Is All You Need
Understand self-attention
Study positional encoding
Understand multi-head attention
Study the encoder and decoder
Implement a basic Transformer
```

Instead of leaving these as a list of things I *should* do, Little Day can find available time and turn them into actual time blocks.

## How it works

One of the design decisions I made in this project is to separate **AI reasoning** from **actual scheduling**.

### AI layer

Gemini is used when I need natural-language understanding.

For example, when I enter a goal, Gemini determines:

* What smaller tasks are needed
* The order in which they should be approached
* A rough duration for each task
* The priority of each task

The AI returns structured data rather than directly controlling my calendar.

### Scheduling layer

The actual scheduling is handled by Python.

The scheduler looks at the tasks generated by the AI and the commitments already stored in Little Day.

It then:

1. Finds the user's available hours.
2. Removes existing commitments.
3. Finds the remaining free time slots.
4. Checks whether a task fits.
5. Places the task into an available slot.
6. Moves on to the next task.

This means the AI doesn't get to randomly decide that I have a class at a time when I actually don't.

The AI helps decide **what needs to be done**.

The scheduling system decides **where it can actually fit**.

## Tech stack

**Python**
The main language used throughout the project.

**PySide6**
Used to build the macOS desktop interface.

**SQLite**
Used for local storage of tasks, goals, habits, and commitments.

**Google Gemini API**
Used for breaking natural-language goals into structured tasks.

**QtAwesome**
Used for the application's interface icons.

**PyInstaller**
Used to package the project into a macOS `.app`.

## Project structure

```text
little-day-ai-planner/
│
├── main.py
├── planner.py
├── database.py
├── build_mac_app.py
├── requirements.txt
├── .gitignore
└── README.md
```

### `main.py`

The main desktop application.

It contains the PySide6 interface and the different sections of Little Day:

* Today
* My Goals
* Calendar
* Habits
* Plan My Day
* Settings

### `planner.py`

Contains the AI and scheduling logic.

This is where goals are sent to Gemini, converted into structured tasks, and passed through the scheduling system.

### `database.py`

Handles the SQLite database.

It stores the persistent data used by the application.

### `build_mac_app.py`

Packages Little Day into a standalone macOS application using PyInstaller.

## Running the project

Clone the repository and install the dependencies:

```bash
git clone <repository-url>
cd little-day-ai-planner

python -m venv .venv
source .venv/bin/activate

pip install -r requirements.txt
```

Create a `.env` file:

```env
GEMINI_API_KEY=your_api_key_here
```

Then run:

```bash
python main.py
```

The API key is kept outside the repository and should never be committed to GitHub.

## Building the macOS app

The project includes a build script for creating the desktop application:

```bash
python build_mac_app.py
```

The finished application is generated in:

```text
dist/Little Day.app
```

The application stores its local SQLite database in:

```text
~/Library/Application Support/Little Day/
```

This allows the app to keep its data separate from the application bundle.

## What's next

Little Day is still a work in progress.

The current scheduler is deliberately simple. Eventually, I want it to become much more adaptive.

Some of the things I want to work on next are:

* Replanning when I miss a task
* Handling recurring classes and commitments
* Better prioritization between competing goals
* More flexible scheduling preferences
* Constraint-based scheduling
* Smarter calendar interactions
* Using past behavior to improve future schedules
* Exploring local AI models
* Making the planner genuinely adaptive instead of simply generating a schedule once
